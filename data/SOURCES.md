# Data sources

Every fixture in `data/` carries its source URL and fetch date here. Firms are FICTIONAL (see `src/biddesk/profiles.py`); every solicitation, description, and attachment is real and public.

## Opportunities (real)
- **SAM.gov Get Opportunities Public API v2**, `https://api.sam.gov/opportunities/v2/search`. Documentation: https://open.gsa.gov/api/get-opportunities-public-api/ (read 2026-09-13). Parameters used: `postedFrom`, `postedTo` (MM/dd/yyyy), `ncode` (one NAICS per call), `limit=1000`, `offset`. No `ptype` or set-aside filter at query time so tiering can be shown on the full stream.
- **SAM.gov unkeyed search (the route the sam.gov web app itself calls)**, `https://sam.gov/api/prod/sgs/v1/search/`. Parameters used: `index=opp`, `q=` (empty), `page`, `size=100`, `sort=-modifiedDate`, `mode=search`, `is_active=true`, `naics=<comma-separated codes>`. No API key, no `ptype`/set-aside filter, so the full stream still reaches tiering. Verified live 2026-09-13 ~22:10 and 2026-09-14 02:5x Central: HTTP 200, `application/hal+json`, `_embedded.results[]` plus `page{size,totalElements,totalPages,number,maxAllowedRecords=10000}`. What the hit carries: `_id` (= noticeId), `title`, `type{code,value}`, `publishDate`, `modifiedDate`, `responseDate`/`responseDateActual`, `solicitationNumber`, `isActive`, `organizationHierarchy[]`. What it lacks: the NAICS list, the set-aside code, place of performance and the full description; those come per notice from the public notice JSON below. Every date parameter tried (`modified_date.from` in several formats) returned HTTP 400, and `sort=-publishDate` is not honoured, so the window is filtered **client-side** on `publishDate` (`sam_client.in_window`); the pull pages to exhaustion because results are ordered by `modifiedDate`, which is always at or after `publishDate`. Responses cached in `data/raw/pubsearch_*.json`.
- **Attachment list for a public notice**, `https://sam.gov/api/prod/opps/v3/opportunities/<noticeId>/resources`. No API key; verified live 2026-09-13 (HTTP 200, `application/hal+json`) against notice `e5081111d5e74d3ebae79926a2bc21be`, whose five `resourceId` values matched that notice's existing keyed-API `resourceLinks` exactly. Only rows with `type=file`, `fileExists=1`, `deletedFlag=0` and `accessStatus=public` are kept, ordered by SAM's `attachmentOrder`; each becomes `.../opps/v3/opportunities/resources/files/<resourceId>/download`. Cached in `data/raw/pubres_*.json`.
- Snapshot window: **posted 2026-08-14 to 2026-09-13 (30 days) for red-cedar and sooner-systems**, pulled 2026-09-14 early morning (America/Chicago) over the unkeyed sgs route while the keyed API key was throttled. plains-med stays on its 7-day keyed window (posted 09/06/2026 to 09/13/2026, pulled 2026-09-13 evening). Notices already held from the 7-day keyed pull keep their keyed records; only the notices the wider window adds are normalized from the public routes, so a snapshot now mixes both sources (`meta.source`, `meta.previous_source`, and `description_url` present only on keyed records). The unkeyed route is `is_active=true`, so the added notices are open notices only. `publishDate` is UTC, so a notice posted late in the Central day can carry the next calendar date. The 7-day snapshots and their tiering bench files as they stood before the widening are in `archive/2026-09-13_7day_window/`. Raw responses in `data/raw/` (gitignored, regenerable); normalized notices in `data/snapshot/<firm>.json` with `fetched_at` on every record.
- Notice descriptions: `https://api.sam.gov/prod/opportunities/v1/noticedesc?noticeid=<id>` (the `description` field of each search hit), fetched with the API key, HTML stripped. Cached in `data/raw/desc_*.json`.
- Notice descriptions, fallback: the public notice JSON the sam.gov page itself loads, `https://sam.gov/api/prod/opps/v2/opportunities/<noticeId>` (no API key; `description[].body` HTML, `parent.opportunityId` for the previous version of an amended notice). Used for all 191 snapshot notices on 2026-09-13 after the keyed API returned HTTP 429 (quota code 900804, reset 2026-09-15 00:00 UTC). Cached in `data/raw/pub_*.json`.
- Attachments: the `resourceLinks` of each notice, `https://sam.gov/api/prod/opps/v3/opportunities/resources/files/<id>/download`. Cached under `data/attachments/<noticeId>/` with a `.meta.json` (URL, original filename, content type, bytes, fetch time).
- API key: personal SAM.gov Public API Key (login.gov account, Profile > Account Details). Daily request limits are role-based and not published; every response is cached so the bench and the offline fallback never re-call the API.

## Geography (real)
- **GeoNames postal code files**, fetched 2026-09-13 (America/Chicago) from `https://download.geonames.org/export/zip/US.zip` plus `PR.zip`, `VI.zip`, `GU.zip`, `AS.zip`, `MP.zip` (the US file does not carry the territories, and SAM.gov notices do use `pop_state=PR`). Licence: the `readme.txt` inside each archive (US, PR and MP read directly) says verbatim "This work is licensed under a Creative Commons Attribution 4.0 License." on one line and links `http://creativecommons.org/licenses/by/3.0/` on the next; GeoNames' own version number (4.0) is taken as the licence, the stale 3.0 link is theirs. Fields used: postal code (col 2), place name (col 3), admin1 code (col 5), latitude (col 10), longitude (col 11); for the territory files the USPS code is the file's country code, since their admin1 column holds municipality numbers.
- `data/geo/us_zip_centroids.csv` (zip,lat,lon,city,state): 41,197 rows, one per 5-digit code, first-seen row wins where GeoNames lists a code more than once; coordinates rounded to 4 decimals (about 36 ft). ZIP is written as a 5-character string so leading zeros survive (`00501`, `00784`).
- `data/geo/us_state_centroids.csv` (state,lat,lon): 57 rows, **derived** — the unweighted mean of that state's ZIP centroids from the file above, not an official geographic or population centroid. It is the last-resort fallback when a notice gives only a state, and the precision label `state` marks any distance computed from it.
- Used by `src/biddesk/geo.py` for the owner distance rule only. Over `data/snapshot/red-cedar.json` (66 notices) it resolves 43 at ZIP precision, 7 at city, 2 at state, 14 unknown (13 notices carry no place of performance at all, 1 is in Gabon). The 2 state-precision rows are notices whose `pop_city` SAM.gov filled with junk (`"0"` in UT, `"46357"` in KS) and no ZIP.
